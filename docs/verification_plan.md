# Verification plan

Each block's specification is broken into numbered requirements, and each
requirement is mapped to the property that checks it, the kind of check, and
how it is closed. Property names carry their role: `a_` specification
assertion, `h_` helper lemma, `c_` cover, `m_` environment assumption.

"k-induction" means an unbounded proof: the property holds in every reachable
state, for any number of cycles. "Bounded" means checked by bounded model
checking to a fixed depth only. Current results are in
[`results/summary.md`](../results/summary.md), generated by `make all`.

Common setup for all three blocks: every input is free (the solver chooses it
on every cycle) unless the plan says otherwise; reset is forced in the first
cycle only and is free afterwards, so every property also covers a reset
arriving in the middle of traffic; all properties except `a_reset` are
disabled while reset is high.

## sync_fifo

First-word fall-through FIFO, parameters `WIDTH` (8) and `DEPTH` (4).
No environment assumptions: the FIFO ignores a push while full and a pop
while empty, so it must be correct for any input sequence.

| # | Requirement | Property | Closed by |
|---|---|---|---|
| F1 | Occupancy never exceeds `DEPTH` | `a_count_range` | 1-induction |
| F2 | `full` is high exactly when `DEPTH` entries are held | `a_full_flag` | 1-induction |
| F3 | `empty` is high exactly when no entry is held | `a_empty_flag` | 1-induction |
| F4 | `count` changes by exactly the operations that took effect; an ignored push or pop leaves it unchanged | `a_count_up`, `a_count_down`, `a_count_hold` | 1-induction |
| F5 | Reset empties the FIFO | `a_reset` | 1-induction |
| F6 | Every entry is delivered unchanged, in order, exactly once | `a_track_inside`, `a_data_order` | 1-induction, assuming `h_tracker_inv` |
| L1 | Lemma: the tracked value sits `ahead` slots after the read pointer | `h_tracker_inv` | 1-induction, on its own |

F6 is checked by following one symbolic entry rather than modelling the whole
FIFO. A free input picks which push to follow; the testbench records its value
and how many entries were ahead of it, and checks that it is on `pop_data`
exactly when that count reaches zero. Because the solver may pick any push and
any data, a proof covers every entry. A loss, duplication or reordering moves
some entry off its expected position, and the solver can choose to follow
that entry.

Covers (each must be reachable, or a property above could pass vacuously):

| Cover | Scenario |
|---|---|
| `c_full` | FIFO fills |
| `c_full_to_empty` | fills, then drains completely |
| `c_push_pop_full` | push and pop together while full (the push is dropped) |
| `c_rd_wrap` | a pop wraps the read pointer through its full range |
| `c_track_deep` | the tracked entry enters behind `DEPTH-1` others |
| `c_track_out` | the tracked entry is popped, so F6's consequent is exercised |

## rr_arbiter

Combinational-grant round-robin arbiter, parameter `N` (4).

Environment: a requester holds its request until it is granted. This is
modelled in the stimulus, not assumed: the arbiter sees any new request plus
every request it left ungranted last cycle (`pending_q`). That produces exactly
the request patterns the rule allows.

| # | Requirement | Property | Closed by |
|---|---|---|---|
| A1 | At most one grant per cycle | `a_one_grant` | 3-induction |
| A2 | A grant goes only to a requester | `a_only_req` | 3-induction |
| A3 | Work-conserving: never idle while someone requests | `a_work_cons` | 3-induction |
| A4 | Every request is granted within `N-1` cycles | `a_wait_bound` | 3-induction |
| A5 | Every request is granted eventually (liveness) | `a_eventually` | bounded only; implied by A4 |

A4 and A5 are written once for a symbolic index `idx`, chosen freely during
reset and then held. A proof therefore covers all `N` requesters, with one
property instead of `N` copies.

| Cover | Scenario |
|---|---|
| `c_wait_max` | a requester waits exactly `N-1` cycles, so the A4 bound is tight |
| `c_all_req` | all requesters at once |
| `c_wrap` | priority wraps from requester `N-1` to requester 0 |

## skid_buffer

Valid/ready skid buffer, parameter `WIDTH` (8).

Environment: the upstream follows the valid/ready rules. Once it raises
`s_valid` it keeps `s_valid` and `s_data` steady until the beat is accepted.
This is built into the stimulus (`held_q`), not assumed. `m_ready` is free:
the downstream may stall on any cycle.

| # | Requirement | Property | Closed by |
|---|---|---|---|
| S1 | A stalled output beat stays valid and unchanged | `a_down_hold` | 1-induction, assuming `h_skid_inv` |
| S2 | Reset clears the buffer and raises `s_ready` | `a_reset` | same |
| S3 | At most two beats are held | `a_occ_max` | same |
| S4 | `s_ready` is high exactly when there is room | `a_ready` | same |
| S5 | `m_valid` is high exactly when a beat is held | `a_valid` | same |
| S6 | No added bubbles: one cycle after `m_ready`, `s_ready` is high | `a_no_bubble` | same |
| S7 | Every beat is delivered unchanged, in order, exactly once | `a_track_inside`, `a_data_order` | same |
| S8 | No combinational path from `m_ready` to `s_ready` | (structural) | by construction: `s_ready = !skid_valid`, a register; checked in review |
| L1 | Lemma: the port-level count matches the two registers, and the tracked beat is in the output register or the skid register | `h_skid_inv` | 1-induction, on its own |

Occupancy for S3–S5 and S7 is counted at the ports (beats accepted minus
beats delivered), so these are black-box requirements. Only the lemma looks
inside the design.

| Cover | Scenario |
|---|---|
| `c_skid_used` | a beat arrives during a stall and lands in the skid register |
| `c_full` | two beats held |
| `c_stream` | four consecutive cycles at full rate on both sides |
| `c_src_waits` | the upstream has to hold a beat |
| `c_track_skid` | the tracked beat waits in the skid register |
| `c_track_out` | the tracked beat is delivered |

## Bug hunting

[`bugs/bugs.toml`](../bugs/bugs.toml) holds 14 seeded bugs, five or four per
block. Each is a plausible design mistake, not a random mutation.
`make bugs` applies each to a copy of the RTL and runs bounded model checking.
A bug counts as caught only if a specification assertion fails; a lemma
failing alone would not count.
